# EOS table consistency

Thermodynamic identities of a regular (log10 P, log10 T) table, written as relative residuals that vanish for an exact equation of state: `cp = T (ds/dT)_P`, the Maxwell relation `(ds/dP)_T = -alpha / rho`, `alpha = -(1/rho) (drho/dT)_P`, `(du/dT)_P = cp - P alpha / rho`, `nabla_ad = P alpha / (rho cp)` and `cp - cv = T alpha^2 / (rho kappa_T)`. The derivatives are central differences in ln P and ln T with a step of `k` grid cells; a stencil counts only when all its cells hold numbers of one phase, so a phase boundary or a missing cell never enters a derivative. The input is a table in the layout of `zalmoxis.eos_export.load_paleos_all_properties`.

`check` takes a table on a grid uniform in log10 P and log10 T (it rejects an axis whose log10 values lie more than `4e-9` off a linear fit; the coordinates of the PALEOS tables lie at most `2.1e-9` off, while the Chabrier 2021 tables, stored at fewer digits, lie about `1e-5` off and are not checked; a smooth drift of the step with a spread of `2e-6` lies `8e-7` off and would give false failures with the mean step. A wobble of the true grid that stays below `4e-9` is not caught; the check assumes axes made by `linspace` or `arange` in log10) and tests each cell where 4 cells on each side along the axis of the derivative hold the differentiated column in one phase: a derivative identity fails where the Richardson residual `R_x = (4 R_h - R_2h) / 3` exceeds the round-off floor of the stored values plus twice the h^4 term measured at that cell, `(R_x(2h) - R_x(h)) / 15`; `nabla_ad` is held to its floor alone. Each identity reads only its own columns (`INPUTS`), so a column it does not read never blocks it. `floors` gives that floor for a stored relative precision `eps` (`5e-9` for 9 significant digits). `signs` flags cells with a non-positive density or heat capacity, `cv` above `cp`, or a density that falls with pressure, at the same floor; each condition tests the cells where its values are not NaN, and an infinite value breaks every condition but the density slope. A missing value (NaN) leaves its cells untested; a stored 0 or inf is a value. Where all values an identity reads are present but its residual or bound is not finite, the cell fails; the PALEOS H2O table stores `cp = cv = alpha = 0` in 15,334 cells at 100 to 295 K, which fail in this way, and a column that is 0 or inf everywhere makes every identity that reads it fail. An identity is skipped only when no cell holds all values it reads; a table where every identity is skipped raises. The report tool prints the reason for a skipped identity and names an input column that is 0 or inf in every cell that holds a value.

Resolution at 9 stored digits, measured at one cell of an exact Murnaghan table at 150 points per decade (P = 46 MPa, T = 1,581 K): a single stored value off by `2e-8` (relative) or more fails at the cells one step from it, and by `3e-7` (entropy) or `1e-6` (density) or more also at the cells two steps from it. The exact ideal gas and Murnaghan tables give no failing cell at this precision. `check` raises a smaller `eps` to `EPS_FLOOR = 5e-9`, so every table, also one stored in full double precision, is checked at the 9-digit floor, and a single value off by about `1e-8` (relative) or less is out of reach on any table. `cv` enters only through `cp - cv`, whose floor at low pressure lies far above `1e-6`, so a `cv` fault there is found only when it is large.

Detection of a `1e-6` fault depends on the grid: on the Aragog P-T layout (`check_pt`), on the 200 x 200 grid that PROTEUS writes (rows at 70, 176 and 281 GPa) a planted `1e-6` entropy was found at all four cells one and two steps away from about 2000 K up, at 1 to 3 of them at 730 K and at none at 443 K, where the linear temperature step is large against `T`; a planted `1e-6` density was found at all four from 730 K up and at 3 of 4 at 443 K; two such faults were missed on a 60 x 60 grid, where the measured h^4 term is larger. `check_pt` takes axes that are finite, increasing, with at least 2 points, and uniform or uniform in log within `PT_GRID_FIT = 1e-6` of the step plus the stored precision; its floor adds the rounding of the stored P and T coordinates, taken as the departure of each coordinate from the fit of its axis, so an exact table with 9-digit axes passes and a planted `1e-6` value is still found one and two steps away. Each `check_pt` identity also gives `fill`, the number of fill cells (`1e-15`, written by eos_export for a cell without data) per file: a clipped block inside the valid region counts as missing, and the fill count shows its size. Tables that eos_export writes by linear interpolation of the PALEOS tables hold the identities only to the interpolation error: with the PROTEUS settings (2-phase MgSiO3, 200 x 200, P up to 350 GPa) 86 to 96 % of the tested cells fail, with residuals of about `1e-4`. `tools/validation/eos_table_consistency_report.py` writes every failing cell of a PALEOS-format table to a CSV file.
